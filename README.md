# ZenMoney Token Page

Небольшая страница для получения API-токена ZenMoney. Она показывает токен, копирует его в буфер и хранит несколько аккаунтов в браузере.

Откройте [token.zentable.ru](https://token.zentable.ru/), если вам подходит готовый сервис. Запустите проект локально, если хотите получить токен без обращения к `token.zentable.ru`.

## Два режима работы

| Режим | Адрес | Как код меняется на токен |
|---|---|---|
| Готовый сервис | `https://token.zentable.ru` | Серверный `zen-token-broker` хранит приватный `client_secret` |
| Локальный | `http://localhost:3000` | Браузер обращается прямо к ZenMoney с публичными development-кредами [Zerro](https://github.com/ardov/zerro/blob/master/.env.development) |

В обоих режимах токены остаются в `localStorage` текущего origin. Сервер их не сохраняет.

## Запуск на своём компьютере

Нужен [Bun](https://bun.sh/) 1.4 или новее. В проекте нет сторонних пакетов, поэтому `bun install` не требуется.

```sh
git clone https://github.com/velios/zen-token-page.git
cd zen-token-page
bun start
```

Откройте именно [http://localhost:3000](http://localhost:3000). OAuth-регистрация Zerro возвращает браузер на этот точный адрес. `127.0.0.1` в адресной строке для входа не подходит.

Локальный сервер слушает только `127.0.0.1`. Остановить его можно сочетанием `Ctrl+C`.

Если вы используете [mise](https://mise.jdx.dev/), репозиторий уже фиксирует нужную версию Bun:

```sh
mise trust
mise exec -- bun start
```

## Что происходит после входа

1. Страница отправляет браузер в ZenMoney.
2. ZenMoney возвращает одноразовый OAuth-код.
3. Страница меняет код на access-токен.
4. Страница запрашивает профиль в ZenMoney, чтобы подписать токен логином и ID аккаунта.
5. Токен попадает в `localStorage`. Повторный вход в тот же аккаунт заменяет прежний токен.

Сохранённые аккаунты появляются сразу при следующем открытии страницы. Кнопка «Удалить из браузера» удаляет локальную запись. Она не отзывает токен в ZenMoney.

Хранилища готового сервиса и локальной версии разделены, потому что у них разные origin. Браузер не переносит токены между ними.

## Публичные OAuth-креды

Локальный режим использует `client_id`, `client_secret` и `redirect_uri` из файла [`.env.development` проекта Zerro](https://github.com/ardov/zerro/blob/master/.env.development). Эти значения уже опубликованы самим Zerro и находятся в `public/app.js`.

Такая регистрация работает только с `http://localhost:3000`. Для публикации страницы на другом домене нужна своя регистрация OAuth с подходящим адресом возврата. На произвольном домене фронтенд ожидает маршруты `/auth` и `/exchange` на том же домене. Их предоставляет `zen-token-broker`.

## Разработка

Страница не требует сборки. Основные файлы:

- `public/index.html` содержит разметку;
- `public/styles.css` отвечает за большие и мобильные экраны;
- `public/app.js` хранит аккаунты и выполняет OAuth;
- `src/server.ts` обслуживает локальный режим на `localhost:3000`.

Проверка локального сервера:

```sh
bun test
```

Production-брокер подключает этот репозиторий как git submodule и фиксирует конкретный commit. Изменение `main` здесь не обновляет [token.zentable.ru](https://token.zentable.ru/) автоматически. Для выпуска владелец обновляет ссылку submodule в `zen-token-broker`, запускает проверки и деплой.

## Данные и безопасность

JavaScript на origin страницы может прочитать сохранённые токены. В проекте нет аналитики, внешних шрифтов и стороннего JavaScript. Сервер отправляет Content Security Policy, которая разрешает загрузку кода только с текущего origin и запросы только к ZenMoney.

Не публикуйте access-токен в issue, логе или скриншоте. Тот, кто получил токен, может обращаться к данным вашего аккаунта ZenMoney.
